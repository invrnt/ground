# Language, money and time

The recording and Ground web interface default to English. Telegram messages to workers are Spanish. Source audio, transcripts, product references and document excerpts retain their original language. The demo adds English subtitles to the Spanish voice note.

Assumption: full web language switching is outside this MVP. Keep English web strings in a feature-local `messages.ts` so later translation does not require restructuring. Shared buttons and status labels live only in the shared UI dictionary. Telegram templates live in the ingestion or dispatch module that owns the message; do not concatenate translated sentence fragments.

Use one formatting helper for `en-GB` dates in the web, `es-CO` dates in Telegram, COP money and quantities. Always pass `America/Bogota` from the project. Show the currency code when a bare `$` would be ambiguous. Display unknown costs as `Price to confirm`; never format null as zero.

Persist UTC timestamps. Resolve `mañana a las nueve` from the trusted scenario clock in demo mode or message receipt time in normal mode. For the baseline, Juan's due time is `2026-09-13T14:00:00Z`, displayed as `13 Sep 2026, 09:00`. Supplier delivery statements stay quoted with their source date until converted into an explicit date by validated code or supervisor input.

Store stable IDs independently of labels. `baño dos`, `baño 2` and `Bathroom 2` resolve the same location. Preserve the commercial reference and exact material ID in both languages. A translated label cannot change compatibility.
