# Critical journeys

The release-readiness agent coordinates this shared acceptance once. Prior agents provide scoped evidence instead of repeating the whole journey.

## Main live journey

1. Run preflight and authorized reset. Confirm 62%, eight tile boxes, four cement bags, absolute scenario date and connected users/providers. Open Ana's session in two browsers.
2. Luis sends the actual Spanish audio and a photo replying to it. Observe persisted acknowledgement, 81%, zero boxes, leak evidence and Juan's 09:00 review. Confirm the second browser receives the same version.
3. Open the real Ambiguous task and Drive photo. Confirm Juan and deadline remotely. Open the site's report document.
4. Inspect the 20-box calculation and a real Exa search result. Open a public source and trace at least reference, coverage and price or explicit unknown price. Do not require a fixed merchant or amount.
5. Open the proposal in CopilotKit. Reload while approval is pending. Confirm the same version/checkpoint, exact text and `Demo recipient`; approve once.
6. Observe the send state, one received request, stored message ID and follow-up due time. Open the same Ambiguous document with the request result. Verify HTML/PDF quantities and versions.
7. Export the run and record commit, scenario, models/SDK versions, provider results and links. Use this execution for the main recording when practical.

This checks the external causal chain. A fixture run is useful development evidence but cannot satisfy steps 2 through 6.

Record the supplemental clip if needed for evaluation. Any unobserved item stays marked untested in the release handoff; it is not silently dropped from the product.
