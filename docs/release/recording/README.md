# Recording package

These are editable recording assets, not a completed recording. No demo video, source audio or full-run capture was supplied or fabricated. The exact narration is copied from PRD section 2; record it only alongside the observed results it describes.

Prepare a 1920×1080 capture, visible cursor and Ground's Recording view so framed text is at least 24 px. Keep Telegram, Ground and the authorized Ambiguous workspace ready. Record one uncut causal run before editing. Up to three supplier rows should remain readable. If a wait is removed, add the visible caption `Processing time shortened` over the cut. Never reorder approval ahead of the actual persisted proposal or show Sent before confirmed delivery.

Use `shot-list.csv` for capture cues and `narration-template.srt` as a timing starting point. Re-time subtitles to the actual source audio and narration before publishing. The Spanish voice note should be 12–15 seconds and use the exact text in `narration.md`. A real reply photo must be authorized, contain no unrelated personal information and be linked to that audio. Put the actual file paths, SHA-256 hashes, MIME type, duration/page count and reply relationship in the private runtime manifest. The tracked manifest deliberately remains empty while this media is missing.

Required outputs after the live run:

- `full-run.mkv` or equivalent uncut capture, including waits.
- `ground-120s.mp4`, at most 120 seconds, with English narration/subtitles.
- `supporting-checks.mp4` for invoice/receipt, correction and recovery where not adequately covered by existing technical evidence.
- Actual admin run export and an evidence index connecting source messages, project/run/version, approval, provider message, remote objects and recording times.

Store those outputs privately and provide intended evaluators access through the team's approved sharing mechanism. Do not make Ground, private attachments or provider accounts public. Preserve an authorized evaluator account separately from admin recovery credentials.

Before capture, complete the main journey's provider read-back prerequisites in the runbook. Ambiguous due_date is date-only, so show the exact time in the task description. Open the actual Exa source from this session; price may legitimately be unknown. An RFQ confirms neither a purchase nor a receipt.
